# Word 和 Excel 导入

桌面材料管理支持 TXT、MD、DOCX、XLSX，可以混合追加导入。
新环境安装解析依赖：

```powershell
& 'D:\Anaconda\envs\langchain1.2\python.exe' -m pip install -r requirements-office.txt
```

## 读取范围

- DOCX：按正文顺序读取段落、普通表格的行。保留文件名，并在抽取文本中标注段落或表格位置。暂不读取图片、文本框、页眉页脚、批注、嵌套表格；不提供页码。合并单元格可能重复显示。
- XLSX：读取所有工作表（包括隐藏工作表）的非空单元格，保留工作表名、行号和单元格地址。数字、零、布尔值、日期转为文本；公式明确标记为“未计算”，不读取缓存结果、不运行公式、不加载外部链接。不读取图片、图表、批注；合并区域仅左上角有值。
- DOC、XLS、DOCM、XLSM、密码保护文件不支持。旧格式请先用 Office 另存为 DOCX/XLSX。
- 不执行宏、文档脚本或公式。导入的内容是证据数据，不是程序指令。

## 限制

单文件最多 1 MiB，材料库最多 500 个文件，原始文件总大小最多 20 MiB，
抽取正文的 UTF-8 总量最多 20 MiB。支持递归导入文件夹及区分不同目录的同名来源，
具体规则见 [本地材料保存](MATERIAL_STORAGE.md)。
Office 解压内容最多 20 MiB / 2000 个压缩条目，抽取正文最多 1 MiB。
Excel 每表最多 20000 行、200 列，全工作簿最多扫描 100000 单元格。
这些限制是当前小型本地原型的保护边界，不代表支持任意大型 Office 文件。
读取失败显示错误，其他有效文件仍可导入。重建索引后才能查询。

证据的“字符起点”对应抽取后的文本，不是 Word 页码或 Excel 行号。
Excel 位置写入证据文本；较长的行切分后可能无法在每个片段保留完整行标记。
当前 RAG 只做文本检索问答，不保证精确表格聚合、财务计算或复杂表格推理。
桌面材料和向量索引支持持久保存；已有有效缓存时重启自动恢复，详见 [本地材料保存](MATERIAL_STORAGE.md)。

## 本轮手动验收

1. 在小 DOCX 中写“项目代号是青竹”，在普通表格中写“负责人：林晓”。
2. 在小 XLSX 中设置工作表“预算”，A1 写“预算金额”，B1 写 300。
3. 启动桌面，逐个导入；材料管理中确认两份均存在，预览能看到对应文字和位置。
4. 重建索引，问“项目代号、负责人和预算金额分别是什么？”。先核对检索原文；需要回答时再明确勾选 DeepSeek 付费生成。
5. 核对答案与原文、引用对应关系。测试文件是自编功能测试资料，不是正式评测证据。
