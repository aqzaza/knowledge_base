# 多文件集容量测试

以下首次测试记录描述的是扩容前版本。当前版已支持最多 500 份、原始文件及
抽取正文各 20 MiB、递归文件夹导入和同名来源区分；规则见 MATERIAL_STORAGE.md。
后续桌面验收另列，首次结果和失败回答不覆盖或改写。

## 测试范围

2026-10-12，使用用户手动下载的《动手学深度学习》中文仓库资料。
原始目录：`data/stress/d2l-zh-master`，来源为 `d2l-ai/d2l-zh`。
读取 Markdown 文本，不运行仓库中的 Python、安装脚本或书中代码。
保留原始 LICENSE、README 和 config.ini，不改写原始章节。

根目录 LICENSE 内容为 Apache-2.0；config.ini 的书籍版权行声明
CC-BY-SA-4.0 和 MIT-0。测试报告同时记录这两处原文，不把所有书籍内容
笼统标为 Apache-2.0。下载资料及生成缓存已加入本项目 Git 忽略列表，
本轮仅本地测试，不将整个资料集打包发布。
ZIP 未校验 Git commit，报告保存每个测试文件的 SHA-256，以标识本地快照。

只新增隔离的测试脚本，未修改产品的容量规则或问答逻辑。
桌面导入测试使用本次结果目录中的独立 materials.json，不接触真实用户材料库。
后端索引使用独立 backend_index.npz；无付费 API 请求、无模型下载。

## 桌面实际边界

- 一次选择 11 份文件：整批拒绝，导入数为 0，明确提示每批最多 10 个。
- 一次选择 10 份不同名文件：10 份读取并持久保存成功，保存后可恢复。
- 在上述库中再追加第 11 份：仍保留 10 份，提示材料库最多容纳 10 个。
- 两个目录中的同名 index.md：仅接受一份，另一份因同名被拒绝。
- 向材料持久存储提交全部 140 份：数量校验拒绝。

所以桌面产品当前不支持这 140 份资料同时入库。
后端测试为区分章节，单独将 source 标识设为相对章节路径；
这只是测试脚本的适配，不表示桌面已经支持文件夹导入或同名文件。

## 本地回答抽查

使用 Top-3 完整片段分别提问偏置、暂退法、梯度裁剪。
Qwen3 CUDA 三问复用同一进程，实际报告 GPU 加载 37 层；
三问分别约 2.74、1.69、1.69 秒，第一问包含启动与加载。
最后停止本次拥有的本地会话。三次均返回有效引用编号，但不全部通过语义验收。

人工核对结果：

- 偏置：结论与 [1] 原文一致，且带引用。
- 暂退法：主要结论及测试时用于不确定性估计的例外有原文支持；
  但“因为此时不需要标准化”的因果表述不严谨，最后重复的结论没有引用。
- 梯度裁剪：提供的片段支持限制梯度范数、缓解梯度爆炸；
  Top-3 没有提供“不能应对梯度消失”的完整依据，回答却自行补充该结论及解释，
  且该句没有引用。虽然全书参考原句确实如此，但本次给模型的证据不足，
  属于证据约束未被严格遵守，不能判为可靠回答。

本轮暴露的主要问题：产品数量上限、同名来源、相关片段未覆盖完整问题，
以及引用编号校验无法发现未被证据支持的结论。尚未修复，不宣称消除幻觉。
下一小任务优先让桌面实际接收多文件资料集；检索与生成可靠性另行修复和复测。
